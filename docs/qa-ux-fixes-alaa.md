# Alaa’s NeuroAdapt UX findings

Developer verification for `fix/alaa-ux-findings`, based on Alaa Hassan’s seven-page desktop UX report dated November 27, 2026. The baseline frontend came from `b7db835`. Both `9aa0069` and `b7db835` are ancestors of this branch. Independent retesting remains with Alaa.

## Findings and independent retest instructions

Use both **1536 × 730** and **1920 × 945** CSS-pixel viewports in Edge. Use a disposable database with synthetic accounts and enough users, medications, and assignments to put the target rows below the fold. For server validation checks, enter spaces in the named text input and confirm a **422** response in the Network panel. Empty fields can trigger native validation before the request.

## Verification and evidence

| Check | Actual result |
|---|---|
| Backend `python -m pytest -q` in `backend` | 44 passed. One existing Starlette/AnyIO deprecation warning. |
| Frontend `npm test` in `frontend` | 14 passed. |
| Existing Playwright coverage | 15 passed in two isolated batches. Covered prior Alaa fixes, authentication and role checks, profiles, medication and history workflows, assignments, and monitoring access. |
| Targeted Edge against `b7db835` | 20 baseline reproductions passed at the two specified viewport sizes. The original report used fewer synthetic rows on some pages. The developer run seeded 18 per viewport to ensure the low-row cases started below the fold. |
| Targeted Edge against the UX branch | 20 passed, 10 per viewport, on the final frontend. |
| Production frontend build | Passed using `npm run build -- --configLoader runner`. The default config loader hit a Windows sandbox directory-read restriction. |

The first combined browser run also exhausted the existing per-IP login rate limit and omitted development-mode reset links. The successful existing-suite reruns used fresh MariaDB databases in two batches, with reset links enabled in development mode and SMTP disabled. The rate limit stayed enabled. Targeted baselines and reruns used real FastAPI/MariaDB mutations and validation. The temporary 503 responses were intercepted by Playwright. No real screen reader was used. Keyboard focus, announcements in the DOM and accessibility relationships were asserted.

The final targeted run captured 40 screenshots. Screenshots are stored locally in [baseline browser output](../tmp/alaa-ux/baseline/browser) and [corrected browser output](../tmp/alaa-ux/targeted/browser). The Playwright output folders include the viewport and test case in their names. The discard confirmation is browser-native. The test asserts its prompt and choices, and the screenshot records what remains after dismissal.

To regenerate corrected screenshots, follow the README’s disposable browser environment setup and supply `E2E_ADMIN_EMAIL` and `E2E_ADMIN_PASSWORD`. From `frontend`, run:

```powershell
npm run test:e2e -- alaa-ux-findings.spec.js --trace off --output ../tmp/alaa-ux/retest
```

Run the original browser tests in fresh batches if needed to avoid the shared local authentication rate limit:

```powershell
npm run test:e2e -- alaa-qa-bugs.spec.js alaa-remaining.spec.js --trace off
npm run test:e2e -- development-fixes.spec.js visual.spec.js workflows.spec.js --trace off
```

The tracked changes are limited to the affected frontend flows, targeted tests and this report. The API contracts, backend code, database schema and migrations are identical to `b7db835`. The editor guard applies to Manage Users actions and in-app route changes. As before, authentication-driven session expiry leaves the editor.
